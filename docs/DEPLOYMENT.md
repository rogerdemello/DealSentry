# Deployment Guide

DealSentry ships as a single Node service: the Express API also serves the
built React SPA (on `NODE_ENV=production`). It depends on a Supabase project
(Postgres, plus storage if you use document upload) and, optionally, an AI
provider (Google Gemini or Azure OpenAI). Without an AI provider, proposal
analysis still works through the built-in rule checker; only proposal
*generation* and semantic search need one.

## 1. Prerequisites

- A Supabase project.
- An AI provider key — a Google Gemini API key, or an Azure OpenAI deployment (e.g. `gpt-4o`). Optional but recommended.
- Node 20+ (for non-container runs) or Docker.

## 2. Configure environment

Copy the template and fill in real values:

```bash
cp .env.example .env
```

Key variables (see `.env.example` for the full list):

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Supabase Postgres connection string (used by Prisma migrations) |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY` | Supabase REST/storage client |
| `SUPABASE_SERVICE_ROLE_KEY` | Server-side key that keeps working once Row Level Security is on (see §6) |
| `GEMINI_API_KEY` (+ optional `GEMINI_MODEL`) | AI generation, analysis and embeddings via Google Gemini — takes precedence |
| `AZURE_OPENAI_ENDPOINT`, `OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT` | The same via Azure OpenAI, if no Gemini key is set |
| `ANALYSIS_MODE` | `rules` forces the built-in rule checker instead of the AI |
| `AUTH_MODE` | `demo` (default, no sign-in) or `login` (email + password) — see `docs/AUTH_QUICKSTART.md` |
| `ALLOW_SELF_REGISTRATION` | `true` lets people create their own account (login mode) |
| `NEXTAUTH_SECRET` | JWT signing secret — generate a fresh 32+ byte value (required in login mode) |
| `TRUST_PROXY` | Proxy hops to trust for client IPs (default `1` in production, which suits Render) |
| `API_PORT` | Server port (default `3001`) |
| `PRODUCTION_URL` | Allowed CORS origin in production |

Generate a strong JWT secret:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

> Security: `.env` is gitignored and must never be committed. Rotate any
> credential that has been shared in plaintext (DB password, Azure key,
> `NEXTAUTH_SECRET`).

## 3. Apply database schema

```bash
npx prisma generate
npx prisma migrate deploy
npm run seed   # optional: demo users, rules, templates, sample proposals
```

## 4a. Run with Docker (recommended)

```bash
docker compose up --build
```

This builds the SPA, installs system Chromium (for PDF export), and serves the
app on `http://localhost:3001`. Configuration is read from `.env`.

## 4b. Run with Node directly

```bash
npm ci
npm run build          # builds the SPA into dist/
NODE_ENV=production npx tsx server.ts
```

The server serves the API under `/api/*` and the SPA for all other paths.

## 4c. Deploy to Render (hosted)

The repo ships a `render.yaml` Blueprint that runs the Dockerfile as a web service.

1. **Rotate secrets first** — the Supabase password and any AI key that was ever shared in plaintext.
   (`NEXTAUTH_SECRET` is auto-generated by Render via `generateValue`, so the old one is replaced.)
2. In Render: **New → Blueprint**, connect this GitHub repo, pick the branch. Render
   reads `render.yaml` and creates the `dealsentry` service.
3. Fill in the `sync: false` env vars in the dashboard: `DATABASE_URL`, `SUPABASE_URL`,
   `SUPABASE_ANON_KEY`, and **`GEMINI_API_KEY`** (or `AZURE_OPENAI_ENDPOINT` + `OPENAI_API_KEY`).
   Without an AI key the app still runs; analysis uses the rule checker.
4. Deploy. Once it's live, copy the service URL (e.g. `https://dealsentry.onrender.com`)
   into **both** `PRODUCTION_URL` and `FRONTEND_URL`, then redeploy so CORS + OAuth
   redirects use the real domain.
5. Schema: we reuse the existing Supabase project, so the tables already exist — no
   migration step needed on first deploy. (For semantic search, run
   `prisma/manual/semantic_search.sql` once; see `docs/SEMANTIC_SEARCH.md`.)

Notes:
- The blueprint uses the **free** plan (512 MB). Two caveats: it **spins down after
  ~15 min idle** (slow first request after a lull), and **PDF export may OOM** at
  512 MB even with the Chromium memory flags — if exports fail, bump `plan` in
  `render.yaml` to `starter`/`standard`. Everything else runs fine on free.
- Render injects `PORT`; the server listens on it automatically.

## 5. Verify

```bash
curl -s http://localhost:3001/api/health     # -> {"status":"ok",...}
# On Render: curl -s https://<your-service>.onrender.com/api/health
```

Then open `http://localhost:3001` (in the default demo mode you are signed in
automatically as the seeded admin; with `AUTH_MODE=login`, sign in), create a
proposal, run analysis, and export a PDF — the PDF path exercises the
containerized Chromium, confirming the image is complete.

## 6. Lock down the database (recommended)

Supabase serves every table over a REST API that anyone with the project's anon
key can call. Until Row Level Security is enabled, that key alone can read the
`User` table (password hashes) and the `Integration` table (CRM OAuth tokens).
Fix it once the API is using the service-role key:

1. Copy the `service_role` key (Supabase → Project Settings → API) into
   `SUPABASE_SERVICE_ROLE_KEY` locally **and** in Render, then redeploy.
2. `npm run check:rls` — must print `ready`.
3. `npx prisma db execute --file prisma/manual/enable_rls.sql`
4. `npm run check:rls -- --verify` — confirms the anon key is locked out.

Do not run step 3 before steps 1–2: the API would lose access to its database.

## 7. Known dependency advisories

`npm audit` still reports advisories whose only fix is a major-version upgrade:
`puppeteer` 21→25 (browser-download and WebSocket helpers), `tailwindcss` 3→4
(build-time glob/watch helpers), `react-router-dom` 6→7, and the Prisma CLI.
They sit in browser-download and proxy tooling, build-time tooling and the
Prisma CLI. A review of how the app uses them found no route from request input
to the affected code (Chrome is only launched by the PDF exporter, against HTML
the server builds, and Tailwind runs at build time) — but that is a judgement,
not a guarantee. Plan these upgrades (each needs a visual/PDF regression pass)
rather than running `npm audit fix --force`, which would also *downgrade* Prisma
and Mammoth.

## CI

`.github/workflows/ci.yml` runs on every push/PR to `main`: install →
`prisma generate` → lint → typecheck → test → build. Keep it green before
deploying.
